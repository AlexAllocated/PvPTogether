## Findings and changes

| Finding in the baseline | Resulting behavior |
| --- | --- |
| Current clients moved the cast bar to `CastBarsContainer.castBar` and use `unitNameAnchorStyle`; the old anchor routine required a missing `unitFrame.castBar`. | A current-layout adapter changes bar/name geometry using loaded client constants. Missing or unreadable components defer the operation. |
| Forbidden-query exceptions failed open; child frames, alpha, boolean unit results, and setup tables were not consistently access-gated. | Value/table/field guards reject secrets and inaccessible results before use. Every affected region and anchor is checked. Secret alpha is never read; the tint inherits parent alpha once. |
| Refresh code explicitly continued geometry writes during combat; the combat ticker scanned up to 80 tokens every 0.3 seconds. | Native object permission, protection, anchoring restriction, and anchoring secrecy checks govern primitive operations. There is no combat polling or fixed token ceiling. Visible enumeration and actual-frame hooks feed one coalesced timer. |
| Disable called Blizzard's driver reset, which rewrites shared setup/frame-option tables. | A private journal restores only the primitive properties the addon changed. No addon options are passed to Blizzard setup helpers; no Lua state is written on Blizzard frames or shared tables. |
| Native refreshes and other addons could supersede old snapshots. | Native post-hooks retire only the journal properties that their update actually replaces. Teardown compares observed applied properties with current values and leaves newer third-party changes alone. Font restoration preserves the named font object and height. |
| No removal lifecycle; recycled textures could stay parented to the wrong health bar or display a prior unit's tint. | Token/base mapping is checked against `GetNamePlateForUnit` each pass. Classification is freshly resolved; no secret GUID cache is needed. Each pooled unit frame has one owner. Removal hides owned tint independently of blocked geometry rollback, and replacement health bars get their own texture. |
| Deferred callbacks survived disable/re-enable; blocked reset work could be discarded. | Generation fences invalidate prior lifetimes. Cleanup handles survive restrictions and offscreen removal, and restriction/lifecycle events retry cleanup even while disabled. |
| Hooks were installed on mixin tables after methods may already have been copied to frames; success could be reported with no installed hooks. | Read-only secure post-hooks attach to actual unit frames; individual missing hooks retry. No global/mixin replacement is used. |
| Settings normalization admitted NaN/infinity and arithmetic on unnormalized values; stale picker callbacks could overwrite later settings. | Finite scalar normalization, strict boolean validation, atomic RGB reads, and callback generations cover disable/hide/reset/feature toggles. |
| Legacy shared dropdowns, no enable checkbox, and an unscrollable settings panel. | Addon-owned modern dropdowns, enable control, scrolling, capability explanations, and stale preview-ticker cancellation. Global Classic remains native, with explicit inheritance. |

`pcall` is error containment only. The safety boundary is access checks, object permissions, limited primitive operations, and addon-owned state. Failed safety queries do not authorize a protected write. No CVars, root plate sizes, hit rectangles, global error handlers, or Blizzard setup tables are modified.

Active combat/PvP/encounter/map restrictions are **not an unconditional visual lockout**. Accessible, explicitly unprotected objects may still be updated when `C_RestrictedActions.CheckAllowProtectedFunctions(object, true)` grants permission and anchor-specific checks pass. Protected objects defer while restrictions are active. Unknown unit classifications are skipped rather than interpreted as enemies or NPCs. Owned tint can be hidden during restrictions only when its own permission checks allow it; otherwise its cleanup remains pending.

## Scope and Forever viability

[FOREVER_COMPATIBILITY.md](FOREVER_COMPATIBILITY.md) contains the installed-source references, official guidance, and detailed client test matrix. Forever has modern APIs and modern restrictions despite its low interface number. The adapter uses its loaded bar dimensions and centered/outlined name preferences while retaining native health-container, level, raid-marker, and crowd-control offsets.

Per-category selections customize **bar/name geometry**, not every behavior in a Blizzard preset. Name colors, selection behavior, hit areas, stacking dimensions, and Forever level-badge dimensions remain governed by the global style. The new Classic preset remains global-only because its native implementation also writes cast/selection behavior fields. When global Classic is selected, PvPTogether retains native geometry; optional accessible border tint can still work. These limits are surfaced in the settings UI and product notes. Legacy and Thin can consequently share geometry when their only difference is native name-color policy.

The addon is a viable Forever test candidate, not a confirmed compatible release. No live login, screenshots, gameplay, arena/battleground session, or taint-log session was performed as part of this audit.
